③执行流程总览

main() 函数（约 962 行起）将整个程序拆分为 7 个阶段，下图展示了完整的数据流：

1
启动与环境初始化
ggml_backend_load_all() 动态加载所有可用的 ggml 后端（CPU/CUDA/Metal/Vulkan…）；Windows 上设置 UTF-8 控制台代码页。
2
命令行参数解析
支持 @file 响应文件语法；从 argv 构建 whisper_params；不存在的输入文件会被剔除。
3
模型上下文创建
调用 whisper_init_from_file_with_params 加载 GGUF 模型；可选地 whisper_ctx_init_openvino_encoder 初始化 OpenVINO 编码器；解析 GBNF 语法（若提供）。
4
音频解码（per file）
read_audio_data 将 wav/flac/mp3 解码为 16 kHz 单声道/双声道 float32 PCM，即 WHISPER_SAMPLE_RATE。
5
构建 whisper_full_params
从 whisper_params 映射 30+ 个推理参数；自动选择 greedy 或 beam search 策略；挂载 progress / segment / abort 三类回调。
6
调用 whisper_full_parallel
核心推理入口，内部完成 Mel 频谱 → 编码器 → 解码器 → 采样 → 分段；每生成一个 segment 会触发 new_segment_callback。
7
多格式输出
通过宏 output_ext() / output_func() 一键分发到 8 个输出器（txt/vtt/srt/wts/csv/json/lrc/score）；最后打印 timing 统计并释放 ctx。
✅ 数据流图（文字版）

音频文件 → read_audio_data → vector<float> pcmf32 → whisper_full_parallel → whisper_context（内存中的 segments/tokens）→ whisper_full_get_segment_* → 文件输出 / 控制台打印。

⑤参数解析函数 whisper_params_parse

5.1 设计模式：链式 else if

从 cli.cpp:132-232 可以看到，本函数采用典型的「命令式」参数解析：

for (int i = 1; i < argc; i++) {
    std::string arg = argv[i];

    // 1. "-" 或 "-" 开头的非选项 → 当作输入文件
    if (arg == "-")              { params.fname_inp.push_back(arg); continue; }
    if (arg[0] != '-')           { params.fname_inp.push_back(arg); continue; }

    // 2. 短/长选项映射到同一个字段
    else if (arg == "-t"    || arg == "--threads")   { params.n_threads = std::stoi(ARGV_NEXT); }
    else if (arg == "-bs"   || arg == "--beam-size") { params.beam_size = std::stoi(ARGV_NEXT); }
    ...
    // 3. 未知选项 → 打印 usage 并退出
    else { fprintf(stderr, "error: unknown argument: %s\n", arg.c_str()); ... }
}

5.2 关键技术点

① ARGV_NEXT 宏（cli.cpp:158）

#define ARGV_NEXT (((i + 1) < argc) ? argv[++i] : requires_value_error(arg))

既取下一个参数，又在缺失值时优雅报错（requires_value_error 直接 exit(0)）。

② 响应文件语法 @file（cli.cpp:978-1002）

当 argv[1] 是 @filename 时，整个文件被逐行展开为 argv，方便调用方预先准备超长命令行。

③ 环境变量覆盖（cli.cpp:133-135）

if (const char * env_device = std::getenv("WHISPER_ARG_DEVICE")) {
    params.gpu_device = std::stoi(env_device);
}

通过环境变量隐藏部署时的设备选择。

④ 短选项缩写表

为了减少键入，CLI 提供两套命名：例如 -t / --threads、-bs / --beam-size、-vt / --vad-threshold 等。单字母全部小写、短横线开头；长选项以 -- 开头且更具语义。

5.3 whisper_print_usage

从 cli.cpp:234-311 的实现可以看出，usage 函数采取「格式化字符串逐行打印」的方式：

fprintf(stderr, "  -t N,      --threads N            [%-7d] number of threads ...\n",
        params.n_threads);

%-7d 保证默认值左对齐且占 7 字符宽度，让帮助信息整齐美观。

⑥回调函数设计

whisper C API 通过 4 类回调暴露内部状态，cli.cpp 实现了其中 3 类，是学习「事件驱动」调用风格的范例。

6.1 whisper_print_progress_callback（cli.cpp:353）

static void whisper_print_progress_callback(
    struct whisper_context * ctx, struct whisper_state * state,
    int progress, void * user_data) {
    // 步进式打印，每 progress_step% 输出一次
    if (progress >= *progress_prev + progress_step) {
        *progress_prev += progress_step;
        fprintf(stderr, "%s: progress = %3d%%\n", __func__, progress);
    }
}

通过 whisper_print_user_data 结构体回传参数上下文，避免使用全局变量。

6.2 whisper_print_segment_callback（cli.cpp:362）

这是最长也是最有意思的回调 —— 每当解码器输出一个 segment 时调用。三种呈现模式：

模式触发条件效果
普通文本默认直接 printf 整段文本
置信度着色--print-colors依据 whisper_full_get_token_p 计算 token 颜色（Paul Tol 色盲友好色板）
置信度样式--print-confidence三档 ANSI 样式：高=暗、中=下划线、低=反色
🎨 k_colors 设计要点

k_colors（common.h:287-295）是 7 段渐变色（红→黄→绿），通过对 p（token 概率）做 pow(p, 3) 映射到 0~6 区间，颜色越绿表示模型越确信。

6.3 encoder_begin_callback 与 abort_callback（cli.cpp:1311-1330）

两个回调均用于外部中止推理：

// 每次编码器运行前触发；返回 false 中止
wparams.encoder_begin_callback = [](whisper_context* ctx, whisper_state* state, void* ud) -> bool {
    bool is_aborted = *(bool*)ud;
    return !is_aborted;
};

// 每次计算块前触发；返回 true 中止
wparams.abort_callback = [](void* ud) -> bool {
    bool is_aborted = *(bool*)ud;
    return is_aborted;
};

当前实现中 is_aborted 始终为 false，但保留了接入 GUI / 命令行 Ctrl-C 处理的标准插槽。

7.3 卡拉 OK 视频脚本（cli.cpp:808）

output_wts 生成一个 bash 脚本，调用 ffmpeg 的 drawtext 滤镜制作卡拉 OK 视频：

fout << "ffmpeg -i " << fname_inp
     << " -f lavfi -i color=size=1200x120:duration=" << t_sec
     << ":rate=25:color=black -vf \"";

// 为每个 token 生成三组 drawtext：
//   1. drawtext=...:enable='between(t,T0,T1)'      // 灰色背景
//   2. drawtext=...:enable='between(t,tok_t0,tok_t1)'  // 绿色高亮
//   3. drawtext=...:enable='between(t,tok_t0,tok_t1)'  // 绿色下划线

因此最终视频会出现「逐字高亮」的卡拉 OK 效果。

7.4 输出分发的「宏技巧」（cli.cpp:1341-1356）

#define output_func(func, ext, param, ...) if (param && fout_factory.open(ext, #func)) {\
    func(ctx, fout_factory.fout, params, __VA_ARGS__); \
}
#define output_ext(ext, ...) output_func(output_##ext, "." #ext, params.output_##ext, __VA_ARGS__)

output_ext(txt, pcmf32s);
output_ext(vtt, pcmf32s);
output_ext(srt, pcmf32s);
output_ext(wts, pcmf32s, fname_inp.c_str(), float(pcmf32.size() + 1000)/WHISPER_SAMPLE_RATE, fout_factory.fname_out.c_str());
output_ext(csv, pcmf32s);
output_func(output_json, ".json", params.output_jsn, pcmf32s);
output_ext(lrc, pcmf32s);
output_func(output_score, ".score.txt", params.log_score, pcmf32s);

利用 token 拼接 output_##ext 把函数名重构出来，避免 8 个 if 重复书写；同时通过 __VA_ARGS__ 透传差异化的额外参数（wts 需要音频时长）。

7.5 fout_factory 内嵌结构体（cli.cpp:1120-1167）

这是非常优雅的 RAII 设计：

  • 初始化时确定输出文件基名（fname_out_ 或 fname_inp）。
  • is_stdout（基名为 -）时输出到 /dev/stdout（Windows 下 CON）。
  • 每次 open(ext, name) 会重置文件名为 basename + ext。
  • 多个输出格式（如 .txt + .srt）会写入同一基名的不同扩展名文件。

8.3 遍历输入文件（cli.cpp:1117-1182）

外层 for 循环遍历 params.fname_inp，每个文件独立：

  3. 多语种检查（whisper_is_multilingual）
  4. 打印系统信息（线程数、beam 大小、任务类型等）

🧠 Greedy vs Beam Search 抉择

源码注释（cli.cpp:1221-1223）：

「greedy search：每次选择概率最高的下一个 token，速度快但可能错过更优解。beam search：保留多个候选序列，考虑更多可能性，通常效果更好但计算量大。」

CLI 默认 beam_size=5，因此默认走 beam search；只有显式 --beam-size 1 时才退化到 greedy。

if (whisper_full_parallel(ctx, wparams, pcmf32.data(), pcmf32.size(), params.n_processors) != 0) {
    fprintf(stderr, "%s: failed to process audio\n", argv[0]);
    return 10;
}

这是整个程序的「心脏」。返回值非 0 即报错退出。

⑩设计模式总结

cli.cpp 在工程上展示了 6 个值得借鉴的设计模式：

🏗️ 单一职责的 main
main 函数只做「编排」，把每个步骤委托给独立函数（解析、加载、推理、输出），便于阅读和单元测试。
📦 宏分发输出
通过 token 拼接宏 output_ext 把 8 种输出格式压缩到 8 行调用，新增格式仅需写一个 output_xxx 函数。
🎯 RAII 输出工厂
fout_factory 内嵌结构体，把「单/多输出文件、stdout、扩展名拼接」封装在一个对象里。
🔌 事件驱动回调
progress / segment / abort 三类回调让 libwhisper 与 CLI 展示层解耦，可被 GUI/服务复用。
🎨 控制台着色
Paul Tol 色盲友好色板 + ANSI 样式，兼顾可读性与可访问性。
🌐 多语言支持
UTF-8 token 合并修复、CJK 多字节正确处理、Windows UTF-8 控制台，跨平台细节完善。
