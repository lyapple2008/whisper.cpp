1. 总览与数据流

Whisper 不直接把原始波形送入 Transformer，而是先计算 Log Mel Spectrogram（对数 Mel 频谱图）。 这是语音识别的标准前端：将时域信号转为时频表示，使模型能感知音高、能量随时间的变化。

核心数据结构

struct whisper_mel {
    int n_len;      // 时间帧数（含 30s 零填充后的帧）
    int n_len_org;  // 原始音频对应的帧数（用于时间戳对齐）
    int n_mel;      // Mel 频带数，通常 80
    std::vector<float> data;  // 行主序: data[j * n_len + i]
};

struct whisper_filters {
    int32_t n_mel;   // 80
    int32_t n_fft;   // 201
    std::vector<float> data;  // [n_mel × n_fft] Mel 滤波器矩阵，从模型文件加载
};
Mel 滤波器不在运行时计算。 模型加载时从 .bin 文件读取预计算的滤波器矩阵（whisper_model_load()）， 保证与 PyTorch 原版 Whisper 数值一致。

3. 不同 Whisper 模型下的参数差异

Log Mel Spectrogram 的信号处理流水线（采样率、窗长、帧移、填充、FFT、对数与归一化公式） 在所有标准 Whisper 模型中完全一致，由 include/whisper.h 中的编译期宏和 log_mel_spectrogram() 硬编码决定，不随模型体量变化。

真正随模型变化、且直接影响 Mel 计算的只有模型文件内嵌的超参数，核心是 n_mels 及其对应的 Mel 滤波器矩阵。

3.1 固定 vs 可变参数一览

参数来源典型值是否随模型变化

WHISPER_N_FFT / frame_size编译期宏400（25 ms） 全部相同
WHISPER_HOP_LENGTH / frame_step编译期宏160（10 ms） 全部相同

n_mels / filters.n_mel模型 hparams + filters80 或 128 large-v3 系为 128

量化版本（Q5_0、Q8_0 等）不影响 Mel 计算。 量化只改变 Encoder/Decoder 权重精度；Mel 前端始终用 float32 运算，滤波器矩阵仍以 float 存储于模型文件。

3.4 对计算量与内存的影响

STFT（FFT）阶段与模型无关；Mel 滤波阶段每帧多做 n_mels 次长度为 201 的点积。

80 Mel（tiny → large-v2）

  • 每帧 Mel 点积：80 × 201 ≈ 16 K MACs
  • 30s 音频帧数 n_len_org ≈ 3000
  • mel.data 约 80 × 3000 = 240 K floats ≈ 960 KB
  • 滤波器矩阵 80×201 ≈ 64 KB

128 Mel（large-v3 / turbo）

  • 每帧 Mel 点积：128 × 201 ≈ 26 K MACs（+60%）
  • 30s 音频帧数 n_len_org ≈ 3000（相同）
  • mel.data 约 128 × 3000 = 384 K floats ≈ 1.5 MB（+60%）
  • 滤波器矩阵 128×201 ≈ 103 KB

Encoder 输入张量形状为 [2 × n_audio_ctx, n_mels] = [3000, n_mels]（经 Conv 后再变为 1500 步）。 因此 large-v3 的 Mel 前端输出在频率轴上比 80 Mel 模型高 60%，但时间轴分辨率不变（仍 100 帧/秒）。

4. 音频填充（Reflect + Zero）

在 STFT 之前，log_mel_spectrogram() 对输入 PCM 做两阶段填充， 与 OpenAI whisper/audio.py 行为对齐。

  • 首部反射填充：将 samples[1..200] 逆序复制到缓冲区开头（reverse_copy），避免帧边界突变。
  • 原始音频：从偏移 stage_2_pad（200）处拷贝。
  • 尾部零填充：追加 30 秒静音，使长音频也能按固定 30s 窗口切片处理。
  • 尾部反射填充：再追加 200 个零（代码中 stage_1_pad 区域末尾）。

帧数计算

n_len = (samples_padded.size − frame_size) / frame_step
n_len_org = 1 + (n_samples + stage_2_pad − frame_size) / frame_step

n_len 含 30s 零填充产生的额外帧；n_len_org 仅对应真实音频时长，后续时间戳换算会用到。

5. STFT：Hann 窗 + FFT + 功率谱

多线程 worker（log_mel_spectrogram_worker_thread）按帧索引 i 并行处理， 每帧偏移 offset = i × frame_step。

Step 5.1 — Hann 窗

w[n] = 0.5 × (1 − cos(2πn / N))   （periodic=true，与 PyTorch 一致）

窗函数在进程启动时预计算，存于 global_cache.hann_window[400]。

Step 5.2 — 加窗取帧

for (int j = 0; j < min(frame_size, n_samples - offset); j++)
    fft_in[j] = hann[j] * samples[offset + j];

Step 5.3 — Cooley-Tukey FFT

实现位于 fft() / dft()，使用预计算的 sin/cos 查找表加速。 输入 400 点实信号，输出 400 点复数频谱。

Step 5.4 — 功率谱 |X|²

P[k] = Re(X[k])² + Im(X[k])²    for k = 0 … 200

只保留 Nyquist 以内的 201 个 bin（n_fft = 1 + N_FFT/2）。

代码注释提到使用 pow(x,2) 会导致推理质量下降，因此采用乘法形式计算模平方。

6. Mel 滤波器组 + log₁₀

Mel 滤波

对每个 Mel 频带 j，将功率谱与滤波器权重做点积：

S[j, i] = Σk=0200 P[k] × filters[j × n_fft + k]

对数压缩

M[j, i] = log₁₀(max(S[j, i], 10−10))

结果写入 mel.data[j * mel.n_len + i]，即行 = Mel 频带，列 = 时间帧。

超出真实音频长度的帧（30s 零填充区域）不再做 FFT，直接填入 log10(1e-10) = −10。

7. 动态范围截断与归一化

STFT + Mel 之后，对所有元素做全局后处理（与 PyTorch 版一致）：

  1. 找全局最大值 mmax
  2. mmax -= 8.0 — 保留 top 8 dB 动态范围
  3. 低于 mmax 的值截断到 mmax
  4. 线性缩放：value = (value + 4.0) / 4.0

归一化效果示意

横轴：原始 log₁₀ 能量；纵轴：归一化后值。虚线为 mmax−8 截断线。
double mmax = -1e20;
for (...) if (mel.data[i] > mmax) mmax = mel.data[i];
mmax -= 8.0;
for (...) {
    if (mel.data[i] < mmax) mel.data[i] = mmax;
    mel.data[i] = (mel.data[i] + 4.0) / 4.0;
}

9. 送入 Encoder 的张量布局

Mel 计算完成后存入 whisper_state::mel。 编码时 whisper_encode_internal() 按 mel_offset 切片， 拷贝到 GGML 张量 mel，形状约为 [2×n_ctx, n_mels]。

Mel 频带 j (0→79)
时间帧 i →   data[j × n_len + i] 
// whisper_encode_internal — 切片拷贝到 encoder 输入
for (int j = 0; j < mel_inp.n_mel; ++j)
    for (int i = i0; i < i1; ++i)
        dst[j * 2 * n_ctx + (i - i0)] = mel_inp.data[j * mel_inp.n_len + i];
